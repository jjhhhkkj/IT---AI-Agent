从单 Agent 到生产系统：原生编排、护栏与评测
手写单 Agent 跑通后，很多人会立刻想上多 Agent。但原生开发的技术路径应该反过来：先把单 Agent 做稳，再考虑编排。因为多 Agent 并没有消除复杂性，只是把复杂性转移到了通信、协调和状态一致性上。没有单 Agent 的评测和护栏，多 Agent 只会让错误传播得更快。生产级 AI Agent 系统的关键，是原生编排、护栏和评测三件事。

原生编排首先是任务编排，而不是角色扮演。一个复杂目标可以拆成若干子任务，每个子任务有输入、输出、依赖、验收标准和优先级。编排器负责决定谁来做、何时做、并行还是串行、失败后怎么办。单 Agent 可以用待办列表和状态机完成大部分工作；多 Agent 才需要消息总线、共享黑板或 supervisor 模式。多 Agent 的常见角色包括规划者、执行者、审查者和领域专家，但角色不是越多越好。每增加一个 Agent，就增加一次模型调用、一份上下文、一套权限和一种失败模式。原生开发应先用单 Agent 加工具解决，只有在任务确实需要并行、隔离或专业分工时才引入多 Agent。

通信协议是多 Agent 的命脉。Agent 之间不能靠自然语言随意聊天，而应定义结构化消息：任务编号、发送者、接收者、目标、约束、证据、截止时间、状态和期望输出。消息要可追踪、可重放、可审计。共享状态要区分事实、假设和决策，避免多个 Agent 各说各话。冲突解决机制也很重要：当两个 Agent 给出矛盾结论时，应由审查者或规则层裁决，而不是让模型投票。终止条件必须明确：所有子任务完成、预算耗尽、连续失败或人工中断。没有这些，多 Agent 很容易陷入无限讨论。

护栏是生产系统的底线。输入护栏过滤提示注入、敏感信息和越权请求；工具护栏限制权限、频率、金额和危险操作；输出护栏检查事实、格式、合规和品牌语气；审计护栏记录每一次模型调用、工具执行和人工干预。护栏不是可选项，而是 Agent 能否进入真实业务的前提。尤其要注意最小权限、沙箱隔离、密钥管理、数据脱敏和二次确认。Agent 可以自动执行只读和低风险操作，但高风险动作必须有人类在环。生产环境不追求全自动，而追求可控、可解释、可恢复。

评测让原生系统持续进化。离线评测集应覆盖典型任务、边界案例、对抗输入、工具失败和多轮对话。指标包括任务完成率、工具调用准确率、无效步数、幻觉率、引用正确率、延迟、令牌成本和安全性。在线观测要记录完整轨迹：目标、上下文、模型输出、工具结果、状态变化和最终反馈。通过轨迹分析，可以定位问题发生在规划、检索、工具还是模型层。每次修改提示、工具或路由，都要跑回归评测，避免修一个问题坏三个场景。

部署架构也要原生可控。小规模可以进程内运行；中等规模可拆成服务化模块，用队列处理异步任务；大规模才需要分布式调度和缓存。无论哪种，都要支持超时、重试、限流、熔断、降级和回滚。模型不可用时降级到规则或人工，工具失败时进入补偿队列，预算超限时暂停并告警。最终，零基础手写 AI Agent 系统课的终点，不是写出最复杂的多 Agent 网络，而是建立一个透明、可测、可控、可演进的生产系统。能解释每一步，才能优化每一步；能控制边界，才能真正落地。
